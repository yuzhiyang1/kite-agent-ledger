# 审查贡献范围

1. 阅读仓库 `README.md`、`CONTRIBUTING.md` 和相关模块。在可访问的上游仓库查 Issue 及开放、已合并的 PR，并记录已有实现、相似工作和当前差异。远程不可访问时，说明查重范围。
2. 写清本次要解决的调用方问题、最小改动和 Kite x402 关联，指出源码位置及一个可复现的成功或失败场景。只有 README 或名称提到 KiteAI 时，技术关联仍待证明。
3. 一次变更解决一个明确问题。发现与需求无关的文件变动先确认来源。公共接口、账本结构或大范围重构交维护者确认后再进入实现。
4. 参考实现时遵守许可证，保留源码出处和复用边界。自动同步、机器人或他人贡献按实际作者留存。
