## Webhook 的结构化失败结果

原实现的 JSON 序列化/签名在 try 外，循环对象或 bigint 会直接拒绝 Promise；fetch 拒绝 null/undefined 时读取 err.message 又抛异常。修复把准备放入同一失败边界，保留普通 Error 消息，其他异常用既有通用错误，并只清理已创建的 timer。没有转换 bigint、改变签名/头/正文或自动重试；通知失败不能作为再次付款的依据。

七项新测试原为三过四败，修复后全过；连同现有两项共九项相关测试通过。覆盖序列化失败不发送、任意异常、正常消息、HTTP 200/503 和 HMAC、timer 清理及单次超时。Bun fetch 替身保留 preconnect 属性以满足真实类型，未用强制转换遮掩类型失败。

## Token bucket 的有限安全容量

程序化配置 burst=Infinity 时，剩余额度为 Infinity、重置时间为 NaN，每次都放行；过大浮点容量也可能扣一不变，默认 rps*2 可能溢出。明确给定的非有限 burst 与计算后超出安全扣减范围的容量被拒绝。正常有限 burst、低于 rps 的既有有限回退及小数补充速率保持兼容。

四项回归原为二过二败，修复后全过；十九项相关限流测试通过，包括最大安全边界逐枚扣减。Issue #90 提前说明与 #87 的同模块协作边界：本次只改构造器，#87 只改 reset，代码段与新测试文件不重叠，不冒领其修复。
